# Goal Document: 0.8.0 GitHub Release

## Go / No-Go

- **Judgment**: Go
- **Reason**: The worktree is clean, the historical `0.7.0` release commit is an ancestor of `main`, GitHub authentication is valid, and the requested release boundary explicitly excludes crates.io publishing.

## Target Outcome

The repository has reproducible GitHub release markers for `0.7.0`, `0.8.0`, and the corrective `0.8.1` patch; the current eight-package GPUI release line consistently declares `0.8.1`; local release verification and the full platform matrix pass; `main` and all three tags are present on `origin`; and published GitHub Releases are bound to `v0.8.0` and `v0.8.1`.

## Goal Definition

- **Type**: delivery and quality
- **Boundary**: Add the historical annotated `v0.7.0` tag at `b2993aa`, repair and run the canonical migration and available semantic API checks, update all active package/dependency/documentation versions to `0.8.0`, record and publish the GitHub release, validate the platform matrix, and issue an immutable `0.8.1` patch release when that matrix exposes release-blocking Windows defects.
- **Non-goals**:
  - Publish, yank, or otherwise modify any crates.io package.
  - Rewrite historical documents whose `0.6.x` or `0.7.0` references describe past releases.
  - Change GPUI runtime behavior or public APIs as part of the release mechanics.
- **Deferred work**:
  - Registry publication and ownership management.
- **Verification rule**: Tags must resolve to their intended commits; Cargo metadata must report the latest patch version for all eight migration packages; no active manifest or installation snippet may request a superseded project version; the canonical release script and full platform matrix must pass; and pushed remote refs must match local refs.
- **Evidence source**: Git refs, Cargo metadata, repository searches, `scripts/verify-migration.sh --semver`, and remote ref queries.
- **Pass criteria**: Every local verification command exits successfully, the final patch release commit is pushed to `origin/main`, historical tags remain immutable, `v0.8.1` points to the platform-green patch commit, the latest GitHub Release is published from `v0.8.1`, and crates.io remains untouched.
- **Confidence note**: Local verification covers the full workspace, package archives, compatibility fixtures, formatting, and semantic API checks. Native Linux and Windows runtime behavior remains covered by repository CI rather than this macOS host.
- **Judgment owner**: Automated verification commands and final remote-ref audit.

## Drift Diagnosis

- **Goal drift**: Registry publication was initially coupled to the repository release but is now explicitly excluded.
- **Phase drift**: Tagging `0.8.0` cannot precede a committed, verified version update.
- **Validation drift**: A version-only commit is insufficient without package archives, compatibility tests, and semantic API checks.
- **Compatibility drift**: Historical `0.7.0` migration documentation must remain unchanged while active installation snippets advance to `0.8.0`.
- **Cleanup drift**: Unrelated implementation or documentation cleanup is excluded from the release commit.

## Priority Rationale

- Restore the missing historical tag first so the `0.7.0` boundary cannot accidentally move with later edits.
- Prove the existing release candidate before changing metadata, then verify the exact release commit again before tagging and pushing.
