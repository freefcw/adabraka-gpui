# 0.9 Desktop Release Smoke Checklist

This checklist validates the user-visible desktop and background-app capabilities promised in
`README.md`. Run it against the exact release candidate commit and packaged application build on
real operating systems. Automated unit and visual tests do not replace these checks.

- Commit: `____________________________`

## Common daemon scenario

Use the maintained example unless the release application has an equivalent end-to-end path:

```sh
cargo run -p adabraka-gpui --example daemon_app --locked
```

For Linux, run separate sessions under X11 and Wayland. Do not treat Wayland global-hotkey rejection
as a failure; the public support matrix explicitly marks that capability unsupported.

For every supported platform/backend:

- [ ] The process starts with no visible normal window and remains running.
- [ ] Startup does not panic and emits the native "Application started in background" notification.
- [ ] A tray/status icon or entry is visible with the expected tooltip.
- [ ] Left click, right click, and double click reach the registered tray callback where the desktop
      environment exposes those events.
- [ ] The tray menu opens and contains **Show Overlay**, **Settings**, and **Quit**.
- [ ] **Show Overlay** opens an always-on-top transparent overlay and renders nonblank content.
- [ ] **Settings** opens a normal window; closing it leaves the background process and tray alive.
- [ ] The global hotkey invokes its callback on macOS, Windows, and X11.
- [ ] Launching a second instance does not create another daemon and signals the existing instance.
- [ ] **Quit** exits the process and removes the tray entry without leaving a zombie process.
- [ ] Repeating start/quit three times leaves no stale tray entries or hotkey registrations.

## macOS

Environment: supported macOS release, packaged `.app`, notifications allowed.

- [ ] `QuitMode::Explicit` keeps the application alive after its last window closes.
- [ ] Daemon/background mode has the intended Dock and activation-policy behavior.
- [ ] The menu-bar item and menu callbacks work after closing every application window.
- [ ] The global shortcut works while another application is focused.
- [ ] Notification permission denial produces a recoverable error and does not terminate the app.
- [ ] Auto-launch can be enabled, is reported enabled, starts the packaged app after login, and can
      be disabled again.
- [ ] Explicit quit removes the menu-bar item and global shortcut immediately.

## Linux X11

Environment: a supported desktop with DBus StatusNotifierItem host, notification daemon, and X11.

- [ ] Force/select the X11 backend and confirm rendering uses the X11 path.
- [ ] The SNI tray entry and menu remain usable after all windows close.
- [ ] The XGrabKey global shortcut works while another application is focused.
- [ ] Native notification delivery works through the session notification service.
- [ ] Overlay and click-through behavior work under the target window manager.
- [ ] Enabling auto-launch creates a valid XDG autostart entry; a login session starts the packaged
      app; disabling auto-launch removes or disables the entry.
- [ ] Missing tray host or notification daemon degrades with an error/log, not a panic.

## Linux Wayland

Environment: each supported compositor family, DBus StatusNotifierItem host, notification daemon.

- [ ] Force/select the Wayland backend and confirm rendering uses the Wayland path.
- [ ] The SNI tray entry, menu actions, daemon lifetime, and notifications work.
- [ ] Global-hotkey registration returns the documented unsupported error without panicking or
      preventing the remaining daemon features from working.
- [ ] `WindowKind::LayerShell` opens on a compositor with `wlr-layer-shell` support.
- [ ] On a compositor without `wlr-layer-shell`, opening a layer-shell window returns
      `LayerShellNotSupportedError`; the process remains alive and can still quit normally.
- [ ] Auto-launch enable/login-start/disable works through XDG autostart.

## Windows

Environment: supported Windows release, packaged executable, notifications enabled.

- [ ] The process starts in background mode without requiring an initial visible window.
- [ ] The `Shell_NotifyIcon` tray icon/menu and all callbacks work after every window closes.
- [ ] The `RegisterHotKey` shortcut works while another application is focused.
- [ ] Native notification/balloon delivery works and failure is recoverable.
- [ ] Overlay, always-on-top, and click-through behavior work.
- [ ] Auto-launch can be enabled in the registry, starts the packaged executable after sign-in, and
      can be disabled cleanly.
- [ ] Explicit quit removes the tray icon, unregisters the hotkey, and terminates the process.

## Failure policy

A failure in a capability marked **Yes** in `README.md` blocks the 0.9 release unless the claim is
narrowed before publishing. Record the OS version, desktop/compositor, command, logs, and a minimal
reproduction. Expected unsupported behavior (currently Wayland global hotkeys and layer shell on
unsupported compositors) passes only when it returns a recoverable error rather than panicking.
